## Оптимальный стек

**Язык:** Python 3.12+
**UI:** Streamlit
**БД:** SQLite
**Парсинг:** `requests/httpx`, `beautifulsoup4`, `pandas`, `openpyxl`
**Планировщик:** обычный cron или `systemd timer`
**Уведомления:** Telegram Bot API
**Запуск:** Docker Compose, но можно и без Docker

Почему так:

* Python проще всего для парсинга сайтов, Excel-выгрузок и быстрых скриптов.
* Streamlit даёт базовый веб-интерфейс почти без фронтенда.
* SQLite хватит за глаза: данных мало.
* ГИС Торги можно мониторить через публичную Excel-выгрузку реестра лотов, а не ковырять HTML. У ГИС Торги есть реестр лотов с поиском по ключевым словам и характеристикам, а в выдаче доступны Excel-выгрузки через публичный endpoint `lotcards/export/excel`. ([Торги][1])
* Сайт Выборгского района тоже надо мониторить отдельно, потому что извещения по земельным участкам публикуются на районной “доске объявлений”. ([vbglenobl.ru][2])

## Что должен делать монитор

MVP:

1. Раз в день или раз в 6 часов проверять:

    * ГИС Торги;
    * сайт администрации Выборгского района;
    * опционально агрегаторы, но только как дополнительный радар.

2. Искать участки по критериям:

    * Ленинградская область;
    * Выборгский район желательно, но не строго;
    * площадь от **1000 м²**;
    * ИЖС / ЛПХ / садоводство;
    * аренда, продажа, извещение по ст. 39.18;
    * ключевые локации: Каннельярви, Кирилловское, Гаврилово, Рощино и соседние станции прямого сообщения с Ланской.

3. Сохранять найденные записи в SQLite.

4. Не дублировать старые лоты.

5. Присваивать каждой записи статус:

    * `new`;
    * `interesting`;
    * `ignored`;
    * `applied`;
    * `expired`.

6. Отправлять в Telegram уведомление, если найден новый подходящий участок.

7. Показывать простую веб-морду:

    * список новых лотов;
    * фильтры по станции, площади, типу, статусу;
    * ссылку на оригинал;
    * дедлайн подачи заявлений;
    * кнопку/чекбокс “интересно”, “игнор”, “подал заявление”.

## Модель данных

Таблица `land_items`:

```sql
CREATE TABLE land_items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    source TEXT NOT NULL,
    external_id TEXT,
    title TEXT NOT NULL,
    description TEXT,
    location TEXT,
    station_match TEXT,
    area_m2 INTEGER,
    area_sotka REAL,
    purpose TEXT,
    contract_type TEXT,
    price_text TEXT,
    status TEXT DEFAULT 'new',
    publication_date TEXT,
    application_deadline TEXT,
    auction_date TEXT,
    url TEXT NOT NULL,
    raw_text TEXT,
    content_hash TEXT UNIQUE,
    is_interesting INTEGER DEFAULT 0,
    is_notified INTEGER DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
```

## Логика отбора

Лот считается подходящим, если:

```text
1. В тексте есть хотя бы одна нужная станция.
2. Площадь >= 1000 м², если площадь удалось распарсить.
3. Есть признаки земли/участка.
4. Есть признаки ИЖС, ЛПХ, садоводства или аренды.
5. Нет явных минус-слов.
```

Если площадь не удалось распарсить, запись всё равно сохранять, но помечать `area_m2 = null` и показывать в UI как “требует ручной проверки”.

## Готовый ТЗ-промпт для код-агента

Вот это можно прямо отдавать Claude Code / Codex / другому агенту.

```text
Нужно разработать небольшой Python-проект land-monitor для автоматического мониторинга земельных участков в Ленинградской области.

Цель:
Находить новые извещения и торги по земельным участкам площадью от 1000 м², которые потенциально подходят под загородный участок рядом со станциями Финляндского направления с прямым сообщением до станции Ланская.

Технологический стек:
- Python 3.12+
- SQLite
- Streamlit для простого веб-интерфейса
- requests или httpx для HTTP-запросов
- BeautifulSoup4 для HTML-парсинга
- pandas + openpyxl для чтения Excel-выгрузок
- python-dotenv для переменных окружения
- PyYAML для config.yaml
- Telegram Bot API для уведомлений

Источники данных:
1. ГИС Торги:
   - использовать публичную Excel-выгрузку реестра лотов;
   - фильтровать земельные участки, опубликованные лоты и лоты с приемом заявок;
   - не парсить тяжелый frontend, если можно использовать Excel export endpoint;
   - сохранить URL выгрузки в config.yaml или .env.

2. Сайт администрации Выборгского района:
   - мониторить раздел доски объявлений / извещений;
   - искать публикации по земельным участкам, ст. 39.18, аренде, ИЖС, ЛПХ, садоводству;
   - для каждой найденной карточки сохранять ссылку и сырой текст.

Основные станции/ключевые локации:
- Каннельярви
- Кирилловское
- Гаврилово
- Рощино
- Победа
- Горьковское
- Приветнинское
- Ландышевка
- Межозерное

Минимальная площадь:
- 1000 м²

Положительные ключевые слова:
- земельный участок
- индивидуального жилищного строительства
- ИЖС
- личного подсобного хозяйства
- ЛПХ
- садоводство
- договор аренды
- право заключения договора аренды
- намерении участвовать
- ст. 39.18
- аукцион

Отрицательные ключевые слова:
- нежилое здание
- помещение
- гараж
- коммерческое
- сельскохозяйственное производство
- земельные участки общего назначения

Функциональные требования:

1. monitor.py
   - Загружает config.yaml.
   - Запускает все включенные источники.
   - Получает список потенциальных записей.
   - Нормализует данные.
   - Считает content_hash по source + external_id/url/title/raw_text.
   - Сохраняет только новые записи.
   - Применяет фильтры.
   - Для новых подходящих записей отправляет Telegram-уведомление.
   - Пишет лог в stdout.

2. База данных SQLite
   Создать таблицу land_items с полями:
   - id
   - source
   - external_id
   - title
   - description
   - location
   - station_match
   - area_m2
   - area_sotka
   - purpose
   - contract_type
   - price_text
   - status
   - publication_date
   - application_deadline
   - auction_date
   - url
   - raw_text
   - content_hash UNIQUE
   - is_interesting
   - is_notified
   - created_at
   - updated_at

3. Парсер ГИС Торги
   - Скачать Excel-файл по URL из config.yaml.
   - Прочитать через pandas/openpyxl.
   - Для каждой строки собрать title, description, url, dates, price_text, raw_text.
   - Попытаться распарсить площадь в м² по регулярным выражениям:
     - "площадью 1447 кв. м"
     - "1447 м²"
     - "1447 кв.м"
     - "площадь: 1447"
   - Попытаться определить тип: аренда, продажа, ИЖС, ЛПХ, садоводство.
   - Вернуть список нормализованных словарей.

4. Парсер сайта Выборгского района
   - Скачать страницу списка объявлений.
   - Найти ссылки на извещения.
   - Переходить только по новым или потенциально релевантным ссылкам.
   - Извлекать title, body text, attached links if available.
   - Фильтровать по ключевым словам.
   - Вернуть список нормализованных словарей.
   - Делать паузу между запросами 1-2 секунды.

5. Фильтры
   - Функция is_relevant(item, config) должна возвращать tuple(bool, reasons).
   - Проверять:
     - наличие станции из списка;
     - площадь >= min_area_m2, если площадь известна;
     - наличие положительных ключевых слов;
     - отсутствие отрицательных ключевых слов.

   Сделать простой интерфейс:
   - Заголовок "Land Monitor"
   - Метрики:

   - Фильтры:
     - station_match;
     - source;
     - status;
     - min_area_m2;
     - only_notified / only_new.
   - Таблица записей:
     - дата публикации;
     - дедлайн;
     - станция;
     - площадь;
     - название;
     - тип;
     - источник;
     - ссылка.
   - Карточка выбранной записи:
     - полный текст;
     - ссылка на оригинал;
     - кнопки:
       - "Пометить интересно";
       - "Игнорировать";
       - "Подал заявление";
       - "Истёк срок".
   - Изменение статусов должно сохраняться в SQLite.

8. CLI-команды
   Реализовать:
   - python monitor.py --once
   - python monitor.py --source gis_torgi
   - python monitor.py --source vbglenobl
   - python monitor.py --dry-run
   - streamlit run app.py

9. Docker
   Добавить Dockerfile и docker-compose.yml.
   docker-compose должен поднимать UI:
   - порт 8501
   - volume ./data:/app/data
   - env_file .env

10. README.md
   Описать:
   - установку;
   - настройку .env;
   - настройку config.yaml;
   - запуск проверки вручную;
   - запуск UI;
   - пример cron:
     0 */6 * * * cd /path/to/land-monitor && /usr/bin/python3 monitor.py --once

Критерии приемки:
- Проект запускается локально.
- SQLite создаётся автоматически.
- monitor.py успешно получает данные минимум из одного источника.
- Новые записи сохраняются без дублей.
- Фильтр находит записи по словам "Каннельярви", "ИЖС", "аренда", "39.18".
- UI показывает сохраненные записи.
- Статусы записей можно менять из UI.
- Telegram-уведомления отправляются при появлении нового релевантного участка.
- Ошибки источников не ломают весь мониторинг.
- Код структурирован по модулям и покрыт базовыми тестами для фильтров и парсинга площади.

Важно:
- Не делать сложную авторизацию.
- Не делать полноценную GIS-карту в первой версии.
- Не делать сложный frontend.
- Не использовать тяжелую БД.
- Не полагаться только на агрегаторы торгов.
- Официальные источники должны иметь приоритет.
```

## Мой практический вердикт

Самый простой рабочий вариант:

**Python + Streamlit + SQLite + cron + Telegram.**

Это не “стартап на микросервисах”, а маленький охотничий радар по земле. Его можно сделать за 1–2 вечера в MVP-версии: сначала ГИС Торги + ручной URL Excel-выгрузки, потом добавить парсер сайта Выборгского района.
