# Описание системы Land Monitor

Land Monitor — локальный радар земельных лотов для поиска новых извещений по участкам от 1000 м² рядом со станциями Финляндского направления с прямым сообщением до Ланской.

## Компоненты

- `monitor.py` — CLI-точка входа для ручной или cron-проверки источников.
- `land_monitor/sources.py` — источники данных: Excel-выгрузка ГИС Торги и HTML-раздел объявлений администрации Выборгского района.
- `land_monitor/parsers.py` — нормализация записей, парсинг площади, дат, типа договора и назначения участка.
- `land_monitor/filters.py` — доменный фильтр `is_relevant(item, config)` с причинами решения.
- `land_monitor/storage.py` — SQLite-хранилище `land_items`, автосоздание схемы и дедупликация через `content_hash`.
- `land_monitor/notifier.py` — Telegram-уведомления через Bot API.
- `land_monitor/exporter.py` — экспорт сохранённых записей в `.xlsx` или `.csv`.
- `app.py` — Streamlit UI для просмотра, фильтрации и изменения статусов.

## Поток данных

1. `monitor.py` загружает `.env` и `config.yaml`.
2. Включённые источники возвращают нормализованные словари лотов.
3. Для каждой записи считается `content_hash` по `source + external_id/url/title/raw_text`.
4. Фильтр проверяет станцию, площадь, положительные и отрицательные ключевые слова.
5. Новые записи сохраняются в SQLite без дублей.
6. Для новых релевантных записей отправляется Telegram-уведомление, после успеха ставится `is_notified=1`.
7. UI читает SQLite, показывает метрики, таблицу, карточку записи и сохраняет пользовательские статусы.

## Статусы

- `new` — новая запись.
- `ignored` — пользователь решил игнорировать запись.
- `applied` — пользователь подал заявление.
- `expired` — срок истёк.

## Устойчивость

Ошибки отдельных источников логируются и увеличивают счётчик `errors`, но не останавливают весь запуск. Telegram-ошибки также логируются и не ломают мониторинг.
